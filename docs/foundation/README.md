# AgroVision Foundation

## An Intelligent Computer Vision System for Plant Disease Diagnosis in Kazakhstan

Пакет исследования, проектирования и планирования к этапу **24 октября 2026 года**. Подготовлен с учетом задания, имеющихся GPU и уточнения команды: несколько сельскохозяйственных культур; **сейчас мобильный интерфейс**, общая серверная платформа и возможность последующего React web. Старый архив рассматривается как контекст черновика, а не утвержденная архитектура.

**Рекомендуемая основа:** модульный монолит FastAPI с отдельным worker, PostgreSQL, приватное объектное хранилище; React Native/Expo; общий OpenAPI-контракт; компактный CNN baseline с проверкой переноса. EfficientNet-B0 — стартовый кандидат, финальный выбор производится после сравнения с MobileNetV3-Large и ResNet18.

## Что уже подготовлено и что предстоит проверить

Выполнены исследование первичных источников, составление проектных документов, создание схем и мобильных макетов, структурные проверки артефактов и перекрестное review. Исправлены расхождения в scope, полях группировки, score space, условиях активации bundle и трактовке отказов API/модели.

**Не выполнялись:** аудит актуального Git-кода, скачивание и файловая проверка всех датасетов, GPU-обучение, измерение точности/latency, локальная казахстанская валидация, сборка приложения, реальные интервью, создание настоящих YouTrack-задач и получение отзыва руководителя. API examples и названия результатов в Figma являются демонстрационными. Параметры в YAML — спецификация будущего эксперимента; готовый training runner не входит в пакет.

## Как перенести в монорепозиторий

Сохраните существующий репозиторий и его историю. В отдельной ветке разместите этот пакет в `docs/foundation/` либо распределите материалы по существующему `docs/`, обновив ссылки. В README репозитория добавьте фактические ссылки на документацию, Figma и YouTrack. Не копируйте исследовательские данные, model weights и секреты в обычный Git. Не создавайте пустой app skeleton ради видимости прогресса: код следующего инкремента формирует Codex после аудита текущего состояния.

Файлы проекта можно редактировать по итогам интервью и review. Существенное изменение scope, классов или протокола оценки должно иметь обоснование и ссылку на задачу. Гипотезы не становятся измерениями после переноса в Git.

## Проверка сроков

В начале приложенного задания указан срок «До 22 октября» и форма; раздел минимальных требований назван «24 October». Команда должна уточнить организационный срок формы. План не предполагает автоматическую отправку формы или сообщений другим людям.
